# What PentAGI leaves behind

PentAGI ([vxcontrol/pentagi](https://github.com/vxcontrol/pentagi), first commit March 26, 2026, reviewed at `cffed94`, October 23, 2026) is a Go server with a React console that runs teams of AI agents against a target. A primary agent splits a goal into subtasks and hands them to specialist agents (pentester, coder, searcher, installer, memorist, adviser), which run their commands in a Kali Linux container per engagement. VXControl publishes it as open source with a commercial edition. This page lists what defenders can see, read from the code and from public research. File references are to the repository at `cffed94`.

**Fragility** says what it takes to remove a signal: *code* means editing PentAGI, *config* means an environment variable or the compose file, *flag* means a tool option the agent chooses.

## How it runs

| Part | What it does | Code |
|---|---|---|
| Server | `vxcontrol/pentagi`, runs as root with the host Docker socket mounted. The compose file publishes HTTPS on `127.0.0.1:8443`; the standalone binary listens on plain HTTP `0.0.0.0:8080` | `docker-compose.yml`, `backend/pkg/config/config.go:79-81` |
| Workers | One container per engagement (a "flow") named `pentagi-terminal-<flow id>`, image `vxcontrol/kali-linux` for penetration testing (`debian:latest` otherwise), working folder `/work`, volume `pentagi-terminal-<flow id>-data`, hostname an 8-character CRC32 of the name | `backend/pkg/tools/terminal.go:27,608`, `backend/pkg/docker/client.go:33-34,327-364`, `config.go:66-67` |
| Worker ports | Two ports per flow from 28000 (`28000 + (flow × 2) mod 2000`), published on `0.0.0.0` by default, for listeners the agent sets up | `backend/pkg/docker/client.go:35-44,121-131,405-426`, `config.go:63-65` |
| Commands | Each agent command runs as `sh -c 'trap "" HUP; read -r adj 2>/dev/null </proc/self/oom_score_adj && echo $((adj + 1)) 2>/dev/null >/proc/self/oom_score_adj; exec sh -c "$0"' <command>`. Default timeout 120 seconds, hard limit 20 minutes, with a detach option for long jobs | `backend/pkg/docker/flow_commands.go:9-24`, `backend/pkg/tools/terminal.go` |
| Browser | Pages are fetched by a separate headless browser service, `vxcontrol/scraper` (basic auth `someuser` / `somepass` by default). Each page read starts two requests at once: the content (`/html`, `/markdown` or `/links`) and a full-page screenshot | `backend/pkg/tools/browser.go`, `docker-compose.yml` |
| Search | DuckDuckGo on by default; Google, Tavily, Perplexity, Firecrawl, Searxng and Sploitus optional | `config.go:204-259` |
| Autonomy | `ASK_USER=false` by default, and nine role prompts open with a pre-authorization block. When an agent answers in prose instead of calling a tool, the reflector agent replies in the user's voice | `config.go:25`, `backend/pkg/templates/prompts/*.tmpl` |
| Updates | Every installation POSTs to `https://update.pentagi.com/api/v1/proxy/updates/pentagi/check` every 3 hours, after fetching a proof-of-work ticket | `backend/pkg/server/update/update.go:52`, `config.go:277-283` |

## An exposed PentAGI console

The console shows a sign-in page titled `PentAGI` on HTTPS. Its certificate is self-generated by the container's entrypoint: the issuer is `C=US, ST=NY, L=NY, O=PentAGI, OU=Project, CN=PentAGI CA` and the server certificate is `CN=localhost`, `O=PentAGI`, SAN `pentagi.local` (`scripts/entrypoint.sh:20-42`). `/api/v1/info` answers without a session, and developer builds expose a GraphQL playground and a Swagger UI titled `PentAGI Swagger API` (`backend/pkg/server/router.go`). The favicon hashes to `-1596753120` on Shodan, and the 96-pixel PNG to SHA-256 `2a620e3c…` on Netlas.

RST Cloud counted 459 verified PentAGI consoles on November 2, 2026, about a third on non-default ports (clusters on 8666 and 8765) and about 90 in one network (AS398823), including renamed builds titled `xhackai`, `Specter`, `PentestAI` and `AI Pentest`. Talos found more than 700 reachable instances, and GitGuardian 521 by title on Shodan. An exposed console is not proof of malicious use.

## Signals in model traffic

Where model traffic is inspected, PentAGI requests carry the pre-authorization block (`## AUTHORIZATION FRAMEWORK`, `<authorization_status>`, `operating within a fully authorized penetration testing system`), the reflector heading `TOOL CALL WORKFLOW ENFORCER`, and tool names such as `pentester`, `hack_result`, `memorist_result`, `maintenance_result`, `search_guide` and `store_guide`.

## What has been seen in the wild

- **GTIG and Mandiant** saw PentAGI in incident response engagements from late August 2026. Most activity stayed at WHOIS asset mapping and vulnerability scanning, but some operations reached intrusion and persistence across several organizations. One actor built a customized orchestration platform on the open-source version to scan system integrators and telecommunications companies in Asia from late August to early October 2026; another chained PentAGI with proxy services against the aerospace sector.
- **Hunt.io** tied the host `45.142.193[.]132`, used by an operator exploiting PaperCut CVE-2026-81578 and CVE-2026-82078, to a PentAGI certificate it presented on port 33333 from April 7 to July 6, 2026.
- **Elastic** lists the worker port callbacks, the twin page fetches and the update check as what to watch for.

## What the code does not contain

PentAGI ships no implant, beacon or exploit code of its own beyond what the agents write and the Kali image provides. Elastic notes that PentAGI keeps the code its agents write in a store shared across engagements, so a tool written for one target can reappear against the next.
